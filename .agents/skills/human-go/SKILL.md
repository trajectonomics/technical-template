# Human go

The owner says `go` on an Idea: it is worth drafting. You apply the labels; the owner does not. Only the owner invokes this skill, so never call it yourself.

The rule lives in the "Owner words" section of the Next steps runbook of `trajectonomics/factory`, so it is changed there and never here.

1. **Find the issue.** The argument is `<repo>#<n>`, `trajectonomics/<repo>#<n>` or an issue URL. With no argument, list the owner's queue (open issues labelled `idea-for-human`, then `idea`, then `idea-postponed`, across `trajectonomics`, with `gh search issues --owner trajectonomics --state open --label <label> --json repository,number,title,url`) and ask which one.
2. **Read the rule** from `origin/main` of `factory`, never from memory: `gh api repos/trajectonomics/factory/contents/docs/next-steps-runbook.md -H "Accept: application/vnd.github.raw+json"`. Read "Idea lifecycle" and "Owner words" and follow the row for `go`.
3. **Check the issue.** It must be open and carry `idea`, `idea-for-human` or `idea-postponed`. Otherwise say so and stop; change nothing.
4. **Apply the row.** Remove the idea labels it carries and add `needs-triage` (`gh issue edit <n> -R trajectonomics/<repo> --remove-label ... --add-label needs-triage`). Comment `> *This was generated by AI during triage.*` then `Owner said go.`
5. **Say what you did** in one line with the issue URL, and that a Spec drafter will take it on the next Dispatcher pass. A `go` is not an Approval: the drafter will ask for the owner's yes before the Spec is approved.
