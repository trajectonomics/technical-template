# Human postpone

The owner postpones an Idea: not now, ask again later. You apply the labels; the owner does not. Only the owner invokes this skill, so never call it yourself.

The rule lives in the "Owner words" section of the Next steps runbook of `trajectonomics/factory`, so it is changed there and never here.

1. **Find the issue.** The argument is `<repo>#<n>`, `trajectonomics/<repo>#<n>` or an issue URL, then an optional `30d` (days) or `yyyy-mm-dd` (date). With no argument, list the owner's queue (open issues labelled `idea-for-human`, then `idea`, across `trajectonomics`, with `gh search issues --owner trajectonomics --state open --label <label> --json repository,number,title,url`) and ask which one.
2. **Read the rule** from `origin/main` of `factory`: `gh api repos/trajectonomics/factory/contents/docs/next-steps-runbook.md -H "Accept: application/vnd.github.raw+json"`. Read "Idea lifecycle" and "Owner words" and follow the row for `postpone`.
3. **Check the issue.** It must be open and carry `idea` or `idea-for-human`. Otherwise say so and stop; change nothing.
4. **Work out the date** in Asia/Bangkok: no argument means 90 days (`TZ=Asia/Bangkok date -d '+90 days' +%F`), `30d` means today plus 30 days, a date is used as given. A date in the past is refused.
5. **Apply the row.** Remove the idea labels it carries and add `idea-postponed`. Comment `> *This was generated by AI during triage.*` then a line `revisit: <yyyy-mm-dd>`. The finder brings the issue back to `idea` on or after that date.
6. **Say what you did** in one line with the issue URL and the date.
